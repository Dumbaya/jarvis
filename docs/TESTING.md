| 환경 | 결과 |

| SQLite(메모리) | 208개 통과, PostgreSQL 전용 4개 건너뜀 |

테스트 파일(`backend/tests/Feature/`): Auth, Memo, Jarvis, Schedule, Tasks, Ledger, LedgerRecurring, Usage, Briefing, LlmChain, GeminiClient, Rag (+ 예제).

## 전략

- **두 DB에서 돌린다.** SQLite는 빠르고 설정이 필요 없다. 그러나 이중 예약 배타 제약, CHECK 제약, 벡터 거리 정렬은 PostgreSQL에만 있다. 이런 것은 PostgreSQL 전용 테스트로 두고 CI가 PostgreSQL(pgvector 컨테이너)에서 전체를 돌린다.
- **외부 API는 가짜로 대체한다.** `Http::fake`로 Gemini 응답을, 가짜 임베더로 벡터를 만든다. 실제 호출은 따로 손으로 검증했다(README의 "검증 상태").
- **가짜 임베더는 거짓 통과를 만들 수 있다.** 모든 문장에 같은 기준 성분을 넣으면 "주제 없는 두 문장의 유사도가 1.0"이 된다. 문장마다 다른 칸에 작은 값을 두도록 고쳤다.
- **핵심은 "깨뜨려서 증명"이다.** 보호 장치를 일부러 끄고 테스트가 실패하는지 확인한다.

## 테스트가 틀렸던 사례 (그리고 배운 것)

- **빈 단언**: 응답 본문의 한글이 `\uXXXX`로 이스케이프되어 "한글 문자열이 없다"는 단언이 항상 통과했다. `json_encode(..., JSON_UNESCAPED_UNICODE)`로 풀어서 단언해야 한다.
- **`Http::fake` 누적**: 같은 URL을 두 번 등록하면 먼저 등록한 것이 우선한다. 응답은 한 번에 등록하고, 순서가 필요하면 `Http::sequence()`.
- **`Http::assertSent`**: 하나라도 맞으면 통과한다. 특정 요청을 검사하려면 `Http::recorded()`.
- **`withToken()`**: 헤더가 테스트 끝까지 남는다. 토큰 없는 요청을 보려면 `flushHeaders()`. 토큰을 바꿔 여러 번 요청하면 가드가 이전 사용자를 기억하므로 `$this->app['auth']->forgetGuards()`.
- **시간 고정**: KST `Carbon`을 그대로 `travelTo`하면 벽시계 시각이 UTC로 저장된다. `->utc()`.
- **terminating 콜백**: 같은 앱 인스턴스가 요청을 반복하면 다시 실행된다. 색인을 한 번만 하도록 방어했다.
- **셸 `sed` 변이**: 치환이 조용히 실패해도 테스트는 통과한다 → "방어가 불필요한가?" 오해. 변이 후 `grep`으로 적용 여부를 확인하거나 편집 도구를 쓴다. 이번에 실제로 겪었다.
- **작은 표본**: 무관한 질문 2개로 임계값을 정한 것(→ [RAG_EVAL.md](RAG_EVAL.md)).

## 자동 테스트가 못 잡은 것 (실제로 돌려서 발견)

동시 요청 교착, Accept 헤더 없는 요청의 500, Docker에서의 프런트 빌드 실패, 헬스체크 오류 → [DECISIONS.md](DECISIONS.md#실제-환경에서-검증하다-발견한-버그). 자동 테스트는 필요조건이고, 실제 환경 검증이 따로 필요하다.

README의 "테스트" 절을 보세요. PostgreSQL 실행은 개발 DB가 지워지지 않도록 **반드시 별도 DB `jarvis_test`** 를 씁니다(없으면 `CREATE DATABASE jarvis_test`).

## 검증하지 못한 것

- GitHub Actions를 실제 러너에서 돌리지 않았다(깨끗한 클론에서 같은 단계를 로컬로 재현하고 actionlint로 문법을 검사).
- Groq/OpenRouter/Ollama 클라이언트: 가짜 HTTP 응답 테스트만.
- 화면(React)의 자동 테스트는 없다. 실제 브라우저로 흐름을 손으로 확인했다.
- 한 번 재현되지 않은 UI 지연(자비스 화면의 두 단계가 한 번 시간 초과)이 있었다. 개발 서버 리로드 때문이라는 가설은 확인하지 못했다.
